# Proposal

## Why

10 完成後以實際字型渲染視窗版資產畫面與資產對話框，依 design critique（Nielsen 十大原則、UX laws）評估，找出 15 項可用性問題（7 項中度、8 項輕微）。主要是畫面直接露出內部用語（產品 key `proxmox-ve`、英文欄位名 `缺少 asset_tag`）、標籤重複或閱讀順序顛倒、按鈕「刪除」實際是「標為退役」、對話框關閉後狀態列殘留紅字錯誤，以及資產清單斷行難以掃視。這些都會讓使用者在最常做的「改版本、新增、退役」操作上多花時間或誤解行為，趁資產編修剛上線時一併修正。

## What Changes

- 資產詳情、編輯對話框與狀態列訊息中的目錄產品一律以顯示名稱呈現（例如「Proxmox VE 8.2.2」），產品 key 只在滑鼠提示中出現
- 編輯對話框的欄位錯誤改用介面用語（「必填」、「重要性只能是 1–3」），不出現英文欄位名；必填欄位以「*」標示
- 下拉選單只用左側一個標籤（移除右側重複的「選擇類別」等文字）；「加入元件」標籤移到選單之前
- 未辨識產品列改為「原文與版本 → 處置選單 → 刪除」的順序
- 資產清單改為表格欄位（編號、名稱、未處理數），長名稱不在數字中間斷行，未處理數大於 0 時醒目顯示；名稱與編號相同時不重複顯示
- **BREAKING（介面文字）**：使用中資產的「刪除」按鈕改名為「退役…」，確認對話框標題改為「將 <資產> 標為退役」；行為不變（標為退役、可恢復）
- 危險操作（「退役…」「永久刪除」）以警示色顯示並與一般操作分開
- 對話框關閉（取消、Esc 或儲存成功）時，清除該對話框留在狀態列的驗證錯誤
- 空狀態：資產沒有命中時顯示「沒有命中」，已退役資產另註明退役後不參與比對
- 套件元件只顯示一次版本（名稱不含版本）
- 類別與曝露度以「英文值（中文）」雙語顯示，例如「server（伺服器）」；儲存與匯出仍使用英文值
- 鍵盤：開啟「加入元件」時游標進入搜尋框、加入後游標移到該元件的版本欄；資產清單上 Enter 開啟編輯、Delete 開啟退役確認
- 工具列分組：「新增資產」｜「匯入清冊、下載範本、匯出清冊」｜「顯示已退役」

## Capabilities

### New Capabilities

（無）

### Modified Capabilities

- `gui-console`：修改 GUI asset editing（介面用語錯誤、必填標示、鍵盤焦點、狀態列清除）、GUI asset retirement and purge（「退役…」按鈕與確認標題）；新增 GUI asset presentation（顯示名稱、清單表格、空狀態、雙語值、工具列分組與危險操作樣式）

## Out of scope

- TUI 的對應調整（TUI 有自己的繪製與用語，另開 change）
- 命中、等待區、設定等其他畫面的評估與修正（本次只評估資產畫面與資產對話框）
- 變更清冊與 CLI 使用的英文值（category、exposure）與匯入錯誤訊息（仍使用 Excel 欄名）
- 色彩對比與螢幕閱讀器的完整無障礙稽核（另以 accessibility-audit 進行）
- 新增或變更任何資料、比對或匯入匯出規則；永久刪除、恢復與背景比對的行為不變
- 復原（undo）功能

## Impact

- `crates/gui`：`screens/assets.rs`（清單表格、詳情、工具列、鍵盤）、`dialogs/asset_edit.rs`（標籤、錯誤文字、焦點、未辨識產品列）、`dialogs/purge.rs`（退役確認文字）、`dialogs/mod.rs`（關閉時清除狀態列）
- `crates/frontend`：`asset_form`（欄位錯誤的介面文字、產品顯示名稱）、`data` 或顯示輔助（產品 key → 顯示名稱、類別與曝露度中文名稱）、`workspace/assets` 的成功訊息改用顯示名稱
- `crates/gui/tests`：更新受按鈕與標籤改名影響的 kittest（`asset_edit`、`asset_retire`、`asset_match`），新增本次行為的測試
- README「視窗版」資產編修段落的按鈕名稱
- 無 migration、無 core 行為變更
