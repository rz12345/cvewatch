# Design

## Context

- 資產畫面（`crates/gui/src/screens/assets.rs`）、編輯對話框（`dialogs/asset_edit.rs`）與退役／永久刪除確認（`dialogs/purge.rs`）由 10 建立；評估依據為以實際字型渲染的截圖（見 proposal.md - Why）
- 元件以 `Component::label()`（產品 key 或 purl_full）顯示；目錄（`Settings.catalog`）有每個產品的 `display_name`，但畫面沒有用到
- 欄位驗證錯誤來自 core `validate_record` 的 `FieldError.message`（例如「缺少 asset_tag」），這些訊息同時是 CLI 匯入錯誤（對應 Excel 欄名），不能改 core 的文字
- 下拉選單使用 `egui::ComboBox::from_label`，會在選單右側再畫一次標籤；kittest 以這些標籤找節點
- 驗證失敗時 `save_asset` 把「請修正標示的欄位」寫到狀態列，關閉對話框後不會清除
- 命中畫面已用 `egui_extras` 表格；資產清單是 `selectable_label` 串接的文字

## Goals / Non-Goals

**Goals:**

- 所有使用者用語轉換（產品顯示名稱、類別與曝露度中文、欄位錯誤文字）放在 `cvewatch-frontend`，GUI 只負責呈現；日後 TUI 可直接沿用
- core 與 CLI 的文字、資料與匯入匯出格式完全不變

**Non-Goals:**

- 不重新設計整體版面或配色系統；只調整評估指出的項目
- 不更動其他畫面

## Decisions

### D1. 顯示用語集中在 `frontend::display`

新增 `product_name(catalog, key) -> String`（目錄有此產品時回傳 `display_name`，否則回傳 key）、`component_name(catalog, component)`（產品元件用顯示名稱、套件元件用不含版本的 purl）、`category_label` / `exposure_label`（「server（伺服器）」）。GUI 的詳情、編輯對話框與 `Workspace` 的成功訊息（「已儲存 PVE-01（Proxmox VE 版本改為 8.2.4）」）都經由這些函式。

替代方案：在 core 的列舉加上中文名稱 —— core 的列舉值是資料與 CLI 的契約，中文名稱只是前端呈現，否決。

### D2. 欄位錯誤以前端文字取代

`AssetForm::validate` 把 core 的 `FieldError` 轉成介面文字：必填 → 「必填」、類別或曝露度不在清單 → 「請從清單選擇」、重要性超出範圍 → 「重要性只能是 1–3」；元件列的「缺少 version」改為「請填寫版本」，重複產品訊息改用顯示名稱。判斷依據是 core 新增的 `FieldError.kind`（`Missing`／`NotAllowed`／`OutOfRange`），不解析 core 的訊息字串（見「Code review 修正」）。core 的寫入錯誤（本地驗證之外的少數情況）仍顯示原文。

### D3. 下拉選單只保留左側標籤

改用 `ComboBox::from_id_salt` 並把左側標籤以 `labelled_by` 關聯（`settings/redmine.rs` 已用此作法），畫面上只剩一個標籤、kittest 仍可用「類別」等標籤找到選單。「加入元件」改為左側標籤＋右側選單。必填欄位的標籤為「資產編號 *」「名稱 *」「類別 *」，元件區標題為「元件 *（至少一個）」。

### D4. 資產清單改為表格

以 `egui_extras::TableBuilder` 呈現三欄（編號、名稱、未處理），整列可點選；名稱欄截斷並以提示顯示全文，未處理數靠右、大於 0 時以警示色顯示；已退役列整列灰字並在名稱後加「（已退役）」。名稱等於編號時名稱欄留空，詳情標題也只顯示一次。

### D5. 對話框不把驗證錯誤寫到狀態列

本地驗證失敗時只在對話框內顯示（欄位旁紅字與對話框底部摘要），不呼叫 `report`。寫入失敗（core 拒絕）時對話框顯示失敗原因，狀態列也顯示；對話框以「取消」或 Esc 關閉時，若狀態列仍是這則失敗訊息就清除。成功儲存時狀態列換成成功訊息（原本即如此）。

### D6. 鍵盤焦點與快捷鍵

- 「加入元件」選單開啟的那一幀對搜尋框 `request_focus`（以 `AssetEdit` 的旗標記錄選單剛開啟）
- 加入元件後記下該元件列，下一幀對其版本欄 `request_focus`
- 資產畫面在沒有文字欄位取得焦點、沒有對話框時：Enter 開啟所選 active 資產的編輯、Delete 開啟退役確認（沿用 `shell.rs` 的單鍵處理與「有對話框時不處理」的規則）

### D7. 「刪除」改名為「退役…」，危險操作以警示樣式顯示

詳情的按鈕依序為「編輯」、間隔、「退役…」（警示色文字）；已退役為「恢復」、間隔、「永久刪除」（警示色文字）。確認對話框標題改為「將 <編號> 標為退役」，確認按鈕維持「標為退役」。README 同步修改。

替代方案：保留「刪除」但加副標 —— 按鈕文字與實際行為（可恢復的退役）仍不一致，否決。

### D8. 工具列分組

`新增資產` ｜ `匯入清冊` `下載範本` `匯出清冊` ｜ `顯示已退役`，組間以垂直分隔線區隔；拖放提示移到清單為空時的空狀態與「匯入清冊」的滑鼠提示。

## Risks / Trade-offs

- [按鈕與標籤改名讓既有 kittest 失效] → 同一任務群組內更新 `asset_retire`、`asset_edit`、`asset_match` 的標籤，並新增本次行為的測試
- [core 寫入錯誤仍可能出現產品 key（例如資料庫在儲存前被其他程序修改）] → 本地驗證已用顯示名稱擋下常見情況；剩餘情況顯示 core 原文，不影響正確性
- [清單改表格後列高與捲動行為改變] → 沿用命中畫面的表格設定（固定列高、虛擬捲動）

## Migration Plan

無資料或設定變更；更新 `cvewatch-gui.exe` 即可，回復舊版不影響資料。

## 實作時的決定（/opsx-auto 依建議自行決定）

- **D2 補充：錯誤摘要加上欄位名稱**：欄位旁只顯示「必填」，但 `FormErrors::summary`（不在對話框中顯示時使用，例如 `Workspace::save_asset_form` 的本地驗證回報）若只串「必填」會失去脈絡，因此摘要改為「資產編號：必填」。欄位的介面名稱集中在 `asset_form::field_label`，GUI 的欄位標籤也由它產生（必填欄位再加「 *」）。
- **「至少需要一個元件」的提示**改為「不再使用此資產時請改用「退役…」」，與按鈕改名一致。
- **套件元件的表單列**：`ComponentDraft.product_key` 對套件改存不含版本的 purl（原為含版本的 `purl_full`），版本只在版本欄顯示一次；套件列本來就不產生編修步驟，不影響寫入。
- **類別與曝露度的中文名稱**：network 網路設備、security 資安設備、virtualization 虛擬化、server 伺服器、storage 儲存設備、host 主機；internet 網際網路、dmz DMZ、internal 內部網路、mgmt 管理網路。
- **版本格式警告**（儲存成功但版本無法解析）也改用產品顯示名稱：frontend 依 `VersionWarning` 欄位自行組字，core 的 `describe()`（CLI 匯入使用）不變。
- **Enter／Delete 的生效條件**：文字欄位有焦點、有下拉選單或對話框時不作用（與命中畫面的單鍵相同）；另外任何元件（例如以 Tab 移到的按鈕）有鍵盤焦點時也不作用，讓 Enter 照常按下該元件（code review 修正）。點選清單列不會取得焦點，點選後 Enter 仍開啟編輯。只對選取且顯示中的使用中資產作用。
- **元件的產品 key** 以滑鼠提示（「產品 key：proxmox-ve」）保留在詳情與編輯對話框的版本欄標籤上，方便對照清冊與 CLI。
- **驗證渲染時發現並修正的三項**（不在原評估清單中，屬於本次改版引入或沿用的呈現問題）：
  - 清單的未處理欄改為固定寬度，名稱欄取得其餘寬度（`Column::auto` 第一次排版過寬，名稱被不必要地截斷）
  - 已退役列改用佈景主題的弱化文字色（`Color32::GRAY` 在深色主題下比一般文字更亮，看不出灰字）；選取列的未處理數只用粗體、不加紅色（紅字在選取底色上對比不足）
  - 編輯對話框的版本欄加上最小寬度（Grid 沿用前一幀欄寬，只設 `desired_width` 時版本字串被截斷）

## Code review 修正（一輪）

- **欄位錯誤種類由 core 提供**：core 的 `FieldError` 新增 `kind`（`FieldErrorKind::Missing`／`NotAllowed`／`OutOfRange`），frontend 依種類對應「必填」「請從清單選擇」「重要性只能是 1–3」，不再以欄位類型與空白與否推測（避免 core 日後為文字欄位加規則時誤顯示「請從清單選擇」）。必填欄位集中為 core 的 `validate::REQUIRED_FIELDS`，`validate_record` 與 GUI 的「*」標示共用；`RecordInput::value(field)` 取欄位輸入。core 的訊息文字與 CLI 輸出不變。
- **版本格式警告**改用 core 新增的 `VersionWarning::describe_with(產品名稱)`，`describe()` 改為呼叫它，GUI 與 CLI 的句型只有一份。
- **元件識別字串**：core 新增 `Component::key()`（產品 key 或不含版本的 purl），`AssetForm::from_entry` 與 `display::component_name` 共用。
- **名稱與編號相同時不重複**：`display::shown_name` 供清單與詳情標題共用。
- **重新儲存時清除舊的寫入失敗**：儲存前先清除對話框與狀態列上一次的寫入失敗訊息，再進行本地驗證，避免欄位錯誤旁仍顯示已不適用的失敗原因。
- **版本欄的 egui id** 改以元件列索引區分：重複加入同一產品（驗證會擋下）時兩列不再共用 id。
- **下拉選單選項**只建立一次（`LazyLock`），不在每一幀重新組字。
- **Enter／Delete** 在有元件取得鍵盤焦點時不作用（見上一節）。

## 驗證

### 4.3 以實際字型重新渲染（2026-11-08）

以 `egui_kittest`（`wgpu` + `snapshot` 功能，放在不納入版控的暫存 crate）載入 `%WINDIR%\Fonts\msjh.ttc`、1.25 倍縮放、1280×760，渲染 8 張畫面：資產清單、詳情（FW-CORE、PVE-01）、編輯（PVE-01，含未辨識產品）、欄位錯誤（新增時直接儲存）、加入元件（選單開啟並輸入 `pa`）、已退役詳情（NAS-02）、永久刪除確認、退役確認。
